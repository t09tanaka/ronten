# ronten デザインシステム — 「朱入れ」

ronten（論点）の UI は日本の校閲・朱入れの伝統を設計言語とする。
紙の上の墨文字に校閲者が朱で印を付ける — 色は装飾ではなく判定の意味そのものを運ぶ。

このドキュメントはフロントエンド（`frontend/src/`）の見た目に関する唯一の基準。
UI を追加・変更するときは必ずここのトークンと規則から導出すること。

## 1. カラートークン

すべて `frontend/src/app.css` の `:root` に CSS カスタムプロパティとして定義する。
複数箇所で使う色は必ずトークン化する。コンポーネント内の生 hex は、1 箇所でしか
使わない状態派生色（hover の濃色・無効背景・警告枠など）と `#fff` のみ許す。

| 半紙 hanshi | `--c-panel` | `#F6F4EE` | サイドバー・パネル・ヘッダー背景 |
| 墨 sumi | `--c-ink` | `#211F1C` | 本文テキスト |

### 使用規則

- 判定の三色（朱・松葉・藍）は**判定の意味を持つ場所にのみ**使う。装飾アクセントに流用しない。
  唯一の例外はシンタックスハイライト（§5）: 藍・松葉・黄土はコード内トークンにも使ってよいが、
  朱だけはシンタックスに使わない（朱の排他性が校閲マークの視認性を守る）
- 朱は「校閲者の手が入った痕跡」にのみ使う: request changes（バー・✕マーク）、落款印、
  Submit、削除行、選択中論点の縦罫、削除系アクションの hover
- ダークモードは提供しない（紙のメタファーに合わせライト固定、`color-scheme: light`）

## 2. タイポグラフィ

| ロール | フォント | 用途 |
|---|---|---|
| 見出し | `'Shippori Mincho', 'Hiragino Mincho ProN', 'Yu Mincho', Georgia, serif` | アプリ名・論点タイトル・モーダル見出し |
| 本文 / UI | `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Hiragino Kaku Gothic ProN', Helvetica, Arial, sans-serif` | 説明文・ボタン・リスト |
| コード | `ui-monospace, 'SF Mono', Menlo, Consolas, monospace` | diff・パス・hunk ヘッダー |

- Shippori Mincho は Latin サブセット woff2（OFL）を `frontend/src/assets/fonts/` に同梱し、バイナリに埋め込む。ネットワークからフォントを読み込まない。OFL ライセンス全文は
  `frontend/public/shippori-mincho-OFL.txt` として配布物（埋め込みアセット）に含める
- 見出しは明朝、それ以外はサンセリフ。明朝を本文に使わない（可読性優先）

### 型スケール

| 用途 | サイズ / ウェイト |
|---|---|
| アプリ名 (h1) | 17px / 600（明朝） |
| 論点タイトル (h2) | 20px / 600（明朝） |
| セクション見出し (h3) | 15px / 600（明朝） |
| 本文 | 14px / 400 |
| UI ラベル・ボタン | 13px / 400–500 |
| メタ・バッジ | 11–12px |
| diff コード | 12.5px |

## 3. シグネチャ要素

大胆さはこの二つに集中し、他は静かに保つ。

1. **落款印ロゴ**: トップバー左、朱の正方形（角丸 2px）に白抜き「論」（明朝）。サイズ 28×28px。このツール唯一の紋章であり、他の場所に印形の装飾を増やさない
2. **判定マーク**: サイドバーの判定済み印は判定ごとに記号と色を変える —
   approve = **✓（松葉）** / request changes = **✕（朱）** / comment = **吹き出し（藍）**。
   記号は文化圏に依存しない普遍的なもの（○=正解は日本ローカルの読みなので使わない）を選び、
   色は判定バーと同じ意味色で補強する。未判定の行にも同サイズの破線空円（白鼠）を常時置き、
   マーク列の幅を予約する — 判定でレイアウトが動かず、残作業もひと目で分かる。
   判定確定時に軽いスタンプアニメーション（scale 1.25→1 / opacity 0→1、120ms）。
   プレースホルダは表示時にアニメーションしない。`prefers-reduced-motion: reduce` では無効化。
   モーションはこの一箇所のみ

## 4. コンポーネント規則

- **選択中の論点行**: 左に 3px の朱縦罫（校閲者の欄外マーク）+ `--c-ai-tint` 背景。
  unmapped 論点の選択時は背景を `--c-odo-tint-2` にする
- **判定バー**: 3 連ボタン。未確定はヘアライン枠 + 紙背景、確定時はその意味色の淡色背景 + 意味色の枠と文字
- **Submit ボタン**: 朱の塗り（白文字）。UI で唯一の塗りつぶし主要アクション。
  無効時は `#E9E6DD` 背景 + 白鼠（`--c-ink-3`）文字
- **Abort（最終確認）**: 朱のアウトライン（`--c-shu` の枠と文字、塗りは使わない。
  塗りつぶしは Submit 専用）
- **Cancel・Abort（トップバー）**: ヘアライン枠のゴーストボタン
- **リスクバッジ**: high=朱 / medium=黄土 / low=薄墨 の淡色背景 + 意味色文字（現行踏襲、トークン参照に置換）
- **罫線**: すべて 1px `--c-rule`。影は原則使わずモーダルのみ（`0 8px 30px rgba(33,31,28,.18)`）
- **角丸**: ボタン・バッジ 3–4px、パネル・モーダル 6px。大きい角丸を使わない
- **ショートカットフッター**: `<kbd>` キーキャップ表示（白 `#fff` 背景・ヘアライン枠・mono。
  紙の上に置かれた白いキーキャップとして 1 段明るくする）。フッターはオーバーレイではなく
  通常のレイアウト行として高さを確保し、コンテンツに重ならない
- **comment / request changes 判定の選択**: General comments 欄へ即時スクロールしてフォーカス
  （`i` ショートカットと同じ着地。アニメーションスクロールは環境により停止するため使わない）
- **判定の確定**: approve は選択と同時に確定。request changes / comment は、その論点への
  行コメントか全体コメントが 1 件以上付いて初めて確定する。確定した論点だけが
  reviewed にカウントされ、全論点確定まで Submit は無効。未確定の間、サイドバーは
  破線円のまま（マークは確定の印）
- **フォーカス**: `outline: 2px solid var(--c-ai); outline-offset: 1px` を全インタラクティブ要素に

## 5. シンタックスハイライト

diff 内のコードは highlight.js（厳選 17 文法、拡張子 → 言語マップは
`frontend/src/lib/highlight.ts`）で行単位にハイライトする。

- 配色は**既存トークンからの導出のみ**。朱は校閲者の痕跡専用なので、シンタックスには決して使わない
- マッピング: キーワード = 藍 / 文字列 = 松葉 / 数値・リテラル・属性 = 黄土 /
  コメント = 薄墨イタリック / 関数・型名 = 墨または藍の 600
- 未知の拡張子・2000 文字超の行はハイライトせず素のテキスト（エスケープ済み）で表示する
- テーマ定義は `app.css` の `.hljs-*` ルール（`{@html}` 挿入のためグローバル定義）
- highlight.js の BSD-3-Clause 通知は `frontend/public/highlight-js-BSD-3-Clause.txt`
  として配布物（埋め込みアセット）に含める

## 6. 文言

- 動詞で書く: 「Submit review」「Request changes」。システム都合の語を出さない
- 判定語彙は全画面で統一: Approve / Request changes / Comment（リスト・バー・サマリーで同一表記）
- エラーは事実 + 次の行動。謝らない、曖昧にしない
