### Task 1.1: `--out` の preflight + 原子的 no-clobber 予約

**Files:**
- Modify: `src/review.rs`（`run` 冒頭に preflight、`write_out_atomic` の呼び出し前後、`serve_session`）
- Modify: `src/exitcode.rs`（既存 `OUT_FAILED=15` を流用、新コード不要）
- Test: `tests/review_flow.rs`

**設計（TOCTOU を排除する予約方式）:**
1. サーバー起動前に `preflight_out(path, concerns_path, repo_root) -> Result<OutReservation, String>` を実行:
   - concerns 入力と同一実体（parent canonicalize + file_name 比較）なら拒否
   - `git rev-parse --git-dir --git-common-dir` の結果を canonicalize し、その配下なら拒否
   - repo-root 相対 lexical path に解決できる場合、`git ls-files --error-unmatch -- <rel>` が成功（=tracked）なら拒否
   - ターゲットがディレクトリ / 既存ファイル / symlink なら拒否（メッセージに「前回の結果が残っている場合は移動・削除してから再実行」）
   - 最後に `OpenOptions::new().write(true).create_new(true)`（unix mode 0o600）で**空のプレースホルダを作成して予約**。`create_new` が原子性を保証（exists 確認→rename の TOCTOU なし）
2. `OutReservation` は Drop または明示 cleanup で、Submit 以外の終端（abort/timeout/エラー/シグナル）時にプレースホルダを削除
3. Submit 時は従来どおり tmp 書き込み→`rename`（置換対象は自分が予約したプレースホルダなので安全）
4. preflight は dirty gate より**前**に実行するが、プレースホルダ作成は dirty gate の**後**に行う（untracked として誤検出させない）。→ preflight(検査のみ) → dirty gate → reserve → serve の順

**Produces:** `preflight_out()` / `OutReservation`（PR 内限定、pub 不要）

### Task 3.1: git subprocess の process-group kill + 出力上限（P0-6）

**Files:**
- Modify: `src/gitdiff.rs:612-676`（`wait_with_timeout` / `timed_output` 再設計）
- Modify: `Cargo.toml`（`libc` を unix 限定依存に追加）
- Test: `src/gitdiff.rs` unit tests（fake git スクリプト方式、既存 `wedged_subprocess_is_killed_at_the_deadline` を拡張）

**設計:**
- unix: `CommandExt::process_group(0)` で子を新しい process group に置き、timeout 時は `libc::kill(-pid, SIGKILL)` で group 全体を kill。kill/wait 失敗は無視せず、二次 deadline（+2s）後に明示 `GitError::GitFailed` にする
- reader thread: 上限付き読み込みに変更 — stdout は呼び出し側指定の `max_stdout_bytes`（diff-tree raw: 64 MiB、status: 16 MiB、その他: 8 MiB）、stderr は 8 KiB の ring buffer（末尾優先）。上限到達で読み捨てながら kill をトリガーし `GitError::OutputOverflow`（新 variant、exit は既存 `GIT_FAILED`）
- reader thread の join にも wall-clock deadline を適用（孫プロセスが pipe を握っていても deadline で諦めて kill+return）
- fake git テスト: 巨大出力 / 子孫プロセスが pipe 保持 / 終了しない child / kill 無視（trap）の各ケース

- [ ] `wait_with_timeout` 再設計 + fake git テスト 4 種
- [ ] commit

**Files:**
- Modify: `src/gitdiff.rs`（`FileDiff` に `id: String`、`requires_ack` → `ack_reasons() -> Vec<AckReason>` へ拡張）
- Modify: `src/session.rs`（`Draft.acknowledged_opaque: Vec<usize>` → `acknowledgements: Vec<String>`（file ID）、validate_draft の突合を ID ベースに）
- Modify: `src/server.rs`（payload に `ack_required` / `ack_reasons` を含める）

**設計:**
- `file_id` = SHA-256(`old_path\0new_path\0old_oid\0new_oid\0old_mode\0new_mode`) の先頭 16 hex（同一 commit ペアに対し安定、配列 index 非依存）
- `AckReason`（serde 共有 enum、schemars 対象）: `OpaqueContent`, `GitlinkChanged`, `ModeChanged`, `AddedSymlink`, `DeletedSymlink`, `AddedExecutable`, `RegularToSymlink`, `LfsPointer`, `SubmodulePointer`
- **ack 必須の拡張**: 新規/削除 symlink・LFS pointer を ack 必須に追加。新規 executable は mode バッジ常時表示 + ack 必須（サーバー側ポリシーで固定）
- one-sided mode（added/deleted）もヘッダに常時表示（`added symlink 120000` / `added executable 100755` / `deleted symlink 120000`）
- frontend は `f.ack_required` / `f.ack_reasons` を表示に使うだけ（再計算しない）。`fileNotices` の LFS/submodule 文言は ack_reasons から生成
- draft wire 互換は不要（サーバーとフロントは同一バイナリ同梱）だが、`acknowledged_opaque` フィールド名の残置はしない

- [ ] Rust: file_id + AckReason + ポリシー拡張 + validate_draft ID 化、ユニットテスト（新規 symlink が ack 必須、pure rename は不要、未 ack 422、reason 内容）
- [ ] frontend: 複製ロジック削除・表示切替、vitest 更新
